# RA-026 — Post-quantum primitives and implementation claims

**Research article · Version 0.1 · Published 2026-11-11 (America/New_York) · Not peer reviewed**

**Type:** Technical background and verification review. **Review stage:** Initial critical synthesis. **Data status:** No new empirical dataset or result; proposed comparisons are unrun.

## Research question and argument

A post-quantum security claim should identify the primitive, parameters, role, implementation, and applicable assumptions. Key establishment and signatures solve different problems. A cryptocurrency example or promotional description is not a substitute for identifying the scheme actually used.

## Evidence and limits

[NIST, 2024](REFERENCES.md#pqc) records approval of the 2024 NIST standards for key encapsulation and signatures, including lattice-based and hash-based schemes. [QRL project](REFERENCES.md#qrl) identifies an XMSS-based hash-signature construction, correcting a lattice-based characterization. These records do not certify an entire application or an investment claim.

## Proposed comparison

1. Inventory each algorithm and state whether it establishes a key, signs a message, or performs another role.
2. Resolve scheme names and parameters against the primary specification and implementation revision.
3. Separate mathematical assumptions, implementation correctness, key/state handling, and application integration.
4. Define correctness and interoperability tests before comparing resource costs.
5. Exclude token prices, funding, and adoption rhetoric from evidence about cryptographic security.

## Data needed to assess the claim

| Record | Purpose |
| --- | --- |
| Primitive and purpose | What cryptographic operation is claimed |
| Specification revision | Standard, parameters, and version |
| Implementation identity | Library or protocol revision actually used |
| State assumptions | Requirements relevant to correct key/signature use |
| Evidence scope | Which property was tested or formally argued |

## Interpretation and failure criteria

Using a recognized primitive does not validate every surrounding component. This review is an algorithm-identification method, not a security certification or financial recommendation. No released STP manuscript is claimed as its direct application.

**Vocabulary — Cryptographic primitive: a basic building block such as a signature or key-encapsulation scheme.**
